# tt_bridge cast system: design

How `tt_bridge` will play a body animation, effects and camera feel every time a player uses an active power or weapon ability. It turns Tier C of `docs/research/2026-10-28-spell-and-power-animations.md` into something buildable. The structure copies Iron's Spells (read from its 1.20.1 source), because that is the best-feeling cast system in our mod list and it runs on the same playerAnimator we already ship.

Status: design only. Nothing here is built yet. Build it after the Tier A test (`tt:cast_test`, see the research doc section 9) proves our animations look right in game.

## 1. What a cast is

Every active ability goes through the same four phases. The server owns the timing; the client only plays what it is told.

| Phase | What the player sees | Ends when |
|---|---|---|
| `windup` | Anticipation pose, charge particles at the hands, rising sound | `windup_ticks` pass, or the key is released for a `charged` cast |
| `release` | The fast move, the burst effect, camera shake, the gameplay effect fires on this tick | 1 tick |
| `channel` (optional) | A looping hold pose while a beam or aura lasts | `channel_ticks` pass, or the key is released |
| `recovery` | The eased return to rest | the animation ends |

Cancel rules, checked on the server every tick of `windup` and `channel`: taking a stun, swapping the held item, or Epic Fight starting a hit-stun animation. A cancelled cast plays a short "fizzle" (smoke at the hands, a dull sound) and starts half the cooldown.

## 2. Cast definitions are data

One JSON file per ability in `data/tt/casts/<id>.json` (a datapack, so KubeJS's `kubejs/data/` works and `/reload` picks up changes). Adding a new power is a new file plus one procedure for its gameplay; no new Java.

```json
{
  "item": "tt:harbingers_railblade",
  "trigger": "use_charged",
  "cooldown": 360,
  "windup_ticks": 30,
  "channel_ticks": 0,
  "animations": {
    "windup": "tt:railblade_charge",
    "release": "tt:cast_focus",
    "speed": 1.0,
    "legs": true,
    "first_person": "model"
  },
  "effects": [
    {"at": "windup", "every": 2, "type": "particle", "id": "minecraft:electric_spark", "anchor": "right_hand", "count": 3, "spread": 0.15},
    {"at": "windup", "type": "sound", "id": "minecraft:block.beacon.power_select", "pitch": 1.6},
    {"at": "release", "type": "effek", "id": "tt:rail_lance_beam", "anchor": "eyes", "follow": false},
    {"at": "release", "type": "sound", "id": "minecraft:item.trident.thunder", "volume": 0.9},
    {"at": "release", "type": "shake", "strength": 0.6, "ticks": 6}
  ],
  "action": "tt_bridge:rail_lance",
  "cancel_on": ["stun", "item_swap"],
  "epic_fight": "yield"
}
```

Field notes:
- `trigger`: `use` (right click), `use_charged` (hold right click, release fires), `sneak_attack`, `key` (the Palladium-style ability key), or `event` (fired by another mod's event, for example an Iron's spell cast).
- `animations`: playerAnimator IDs. Our own live in `kubejs/assets/tt/player_animation/` (generated by `tools/gen_animations.py`); Iron's 71 animations (`irons_spellbooks:<name>`) are also valid. `legs: false` masks the legs so walking still animates, as Iron's does for most spells. `first_person`: `model` shows the arms (Iron's `THIRD_PERSON_MODEL` mode); `vanilla` keeps the normal first-person hand.
- `effects[].at`: `windup`, `release`, `channel`, `recovery`, `fizzle`, or a tick number. `every` repeats it every N ticks within its phase.
- `effects[].type`: `particle` (vanilla particles, works now), `sound`, `shake`, and `effek` (an AAA Particles Effekseer effect, only once AAA Particles is in the pack at stage D; until then the loader skips it with one warning).
- `anchor`: `right_hand`, `left_hand`, `eyes`, `feet`, `target` (the entity or block the ability hit). Hand anchors follow the animated arm, so a particle sits on the palm even mid-swing.
- `action`: the procedure that does the gameplay (damage, movement, blocks). It runs on the server on the release tick.
- `epic_fight`: `yield` means that while the player is in Epic Fight battle mode, an Epic Fight animation playing at the same time wins (Epic Fight's own rule through `PlayerAnimatorCompat`); `override` plays ours over it. Weapons whose ability is an Epic Fight innate skill (EDP weapons) don't use this system at all.

## 3. The pieces

### Server (`CastManager`)
- Holds the active cast per player: definition, phase, tick, whether the key is still held.
- Ticks on `PlayerTickEvent` (server side). Fires `effects` and the `action` at the right ticks, so effects and damage can never drift apart.
- Starts the cooldown with the item's cooldown (`player.getCooldowns().addCooldown`) so the hotbar shows it.
- Sends packets to the caster and everyone tracking them:
  - `CastStart(entityId, castId, phase, speed)`
  - `CastPhase(entityId, phase)` (windup → release → channel → recovery)
  - `CastStop(entityId, fizzled)`

### Client (`TTCast`)
- Registers its own `ModifierLayer` on every player at priority 1000 (Iron's uses 42 and Palladium its own layer, so ours sits on top).
- On each packet it calls `replaceAnimationWithFade(AbstractFadeModifier.standardFadeIn(2, Ease.INOUTSINE), anim)`. Two ticks is what Iron's uses: long enough to avoid a snap, short enough that the release stays sharp. (Palladium uses 20 ticks, which is why its powers feel floaty.)
- Adds an `AdjustmentModifier` that tilts the arms and head by the player's look pitch, so a forward cast aims where the player looks.
- Adds a `MirrorModifier` when the item is in the off hand.
- Sets `FirstPersonMode.THIRD_PERSON_MODEL` with arms shown for `first_person: model`.
- Plays client-only effects (hand-anchored particles, camera shake through `ViewportEvent.ComputeCameraAngles`). Hand positions come from the animated arm's pose, read from the layer each frame.

### Weapon animation (GeckoLib, later)
For weapons that should physically move (Choirbreaker vents, Railblade charge coils, Undergloom blade unfold), the item becomes a GeckoLib item and the cast definition gets `"item_animation": {"windup": "charge", "release": "fire"}`, played with `triggerAnim`. The generated `gen_models.py` model stays the look; it is converted to a `.geo.json` once and gets bones. Not needed for the first build.

## 4. Building it in MCreator

MCreator's Player Animator plugin only has a bare "play animation" block, with no fade, stop, layer or sync, so the cast system is custom code elements inside the `tt_bridge` workspace:
1. `TTCastData`: the JSON reload listener for `data/tt/casts/` (a `SimpleJsonResourceReloadListener`).
2. `CastManager`: server tick handler and the public `start(player, castId)` that item procedures call.
3. `TTCastPackets`: the three packets on the mod's `SimpleChannel`.
4. `TTCast`: client layer, modifiers, effects and camera shake.
5. One MCreator procedure per `action` (normal block-based procedures are fine here; they get the player and the target).

Items keep using normal MCreator item triggers; their "right click" procedure just calls `CastManager.start`.

## 5. The BRIDGE abilities as casts

Passive abilities (no button) don't get a cast; they get a short on-hit effect instead.

| Ability | Trigger | Windup → release animation | Release tick | Notes |
|---|---|---|---|---|
| Rail Lance (Railblade) | `use_charged`, 30 ticks | new `tt:railblade_charge` (blade drawn back at the hip, off hand on the spine) → `tt:cast_focus` | on key release | first cast to build; proves beam + shake |
| Gale Vault (Skyreach) | `use` | `tt:cast_blink` crouch → `tt:weapon_raise` in the air | 5 | the plunge is a second cast (`event`: attack while airborne) using `tt:cast_slam` |
| Overload Punch (Choirbreaker) | `use_charged`, 20 ticks | new `tt:gauntlet_charge` (fist pulled back, torso twisted) → `tt:cast_flick` with both fists | on key release | EMP ring effect |
| Pressure Release (Cogwright) | `sneak_attack` | `tt:cast_slam` | 9 | AoE knock-up |
| Prism Ward (Prism Ward Staff) | `event` (Iron's spell cast) | none (Iron's own spell animation plays) | 0 | effects only: barrier shimmer |
| Shard Rend (Crownshard) | `key` | `tt:cast_blink` per jump | 5 | three short casts chained by the action |
| Seedshot (Rootstring), Undertow Arrow (Abyssal) | `event` (fully charged shot) | vanilla bow pose | 0 | effects only |
| Reversal Cut, Iron Recoil, Sunder the Regent, Oath of the Capital | passive | none | n/a | on-hit particles and sound only |

New animations named here are added to `tools/gen_animations.py` when the system is built, and previewed in `blockbench/previews/cast-animations.html` first.

## 6. Test plan
1. One cast (Rail Lance) end to end in single player: windup pose, release on key up, beam damage on the release tick, cooldown on the hotbar.
2. Same on a LAN server with a second player watching: the animation and effects show for the watcher (packets reach trackers).
3. Epic Fight battle mode: `yield` lets an Epic Fight dodge interrupt the pose; `override` keeps it.
4. Cancel: take a hit from a stunning mob mid-windup; the fizzle plays and half the cooldown starts.
5. Off hand: the pose mirrors.
6. `/reload` after editing a cast JSON changes timing without a restart.
